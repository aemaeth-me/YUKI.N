## 0. 一句话

**守住"单一权威原始层 + 证据/建议分离"两条不变量，把召回从"让模型猜"改成"让模型认"，用 SQLite 三轨（确定性 grep + trigram FTS5 + 可选向量）作为检索底座，并补齐评测。** 记忆层数不增加、不做层层 Summary。

---

## 1. 讨论起点与结论回顾

1. **分层共识，但反对层层 Summary。** 层层摘要若满足"每层唯一表示 + 链式压缩 + 唯一顺序读取"，就与 RNN 失效同构（瓶颈即存储）。当前设计的解法是对的：**只有一个权威原始层**（Task Archive + Experience），其余（印象/唤醒包/记忆库）都是带回溯的派生索引；`memory_grep`/`memory_read` 直达原始层——这就是 RNN 缺的外部随机存取。
2. **当前设计整体评估**（对照综述）：防错/可验证族（证据分类、进程排除、诊断禁令、门控写路径、审计恢复）领域领先；召回/更新族（检索混合、知识更新、评测）是缺口。
3. **召回是核心关切。** 印象层本质是"对模型的提醒"而非记忆——提醒器的价值全在"能否把注意力引到正确的原始记录上"。当前 cue 生成的三处短板：
   - 信号源太薄（去事实化印象 + 任务尾部 360 字符预览）；
   - 缓存冻结（`(化身, 线程, intentId)` 只在化身删除时清空，`Cognition.hs:2069`——新档案/印象修订不失效）；
   - 只能"精确串回忆"（cue 的 `suggestedQuery` 必须逐字命中），没有"再认"通道。
4. **对 embedding 的怀疑是合理的**：确定性/回放是硬约束；编码 agent 的记忆以精确标识符为主（词法问题）；语义相似会制造假置信；综述数据（纯向量 ~49% vs 混合 71–95%）。→ **embedding 只配做建议路径，永远不进证据路径。**
5. **SQLite 方向正确。** "把原始记录放进 SQLite，同时支持 grep 与 embedding" = 综述说的混合检索的生产形态。QMD（tobi/qmd）是这条路的现成验证：SQLite+FTS5+sqlite-vec 混合管线（query expansion → BM25+Vector → RRF k=60 → rerank → position-aware blend），被 OpenClaw 等大量采用。**但 QMD 整体不适合 YUKI.N**：默认 `porter unicode61` 对中文 BM25 全哑（issue #617）、query expansion 英文训练会改写中文（issue #454）、Node sidecar + ~2.1GB GGUF 与纯 Haskell 相悖、混合+rerank 非确定。→ **抄它的管线参数与 bench 范式，不引它的运行时与 tokenizer。**

## 2. 必须守住的不变量（红线，任何演进不得破坏）

| # | 不变量 | 依据 |
|---|---|---|
| I1 | **单一权威原始层**：Task Archive + Experience 不可变、append-only，是唯一事实源 | 宪法：派生摘要永不取代原始证据 |
| I2 | **证据/建议分离**：只有 `memory_grep`/`memory_read` 是证据路径；FTS5 / 向量 / rerank 一律只是候选建议，建议必须经 grep/read 验证才可依赖 | 反注入、防幻觉 |
| I3 | **证据轨字节确定**：grep 输出确定、可 golden 测试、可逐字节回放；任何新检索通道不得改变证据轨语义 | Replay 体系 |
| I4 | **记忆是能力不是注入**；cue 永不自动成为事实 | 宪法 |
| I5 | **不层层 Summary**：层可以是索引，不能是"唯一真相"；不引入摘要之摘要链 | 本讨论 §1.1 |

## 3. 演进方向（四条线，按优先级）

### A. 召回线：cue 生成——从"生成"改"选择优先"（retrieve-then-cue）

现状问题：激活模型在几乎看不到目标内容的情况下，凭空构造必须逐字命中的 grep 串（`Impression.hs:538-558`）。

方向：
- **A1 候选优先**：Stage-1 由检索（机器，确定性）给出 top-k 真实候选（条目 ID + 真实预览 + 任务标签）；Stage-2 LLM 从候选里**挑** ≤5 条 cue，而非凭空想。再认 > 回忆。
- **A2 解耦相关性/可执行性**：cue 输出改为 `{语义目标 hint, taskId 锚点, entryIds[], suggestedQueries: 1..N（从真实预览摘取，允许为空→退回任务级 grep）, confidence, reason}`。即使所有串 miss，`taskId` 锚点仍在。
- **A3 修缓存失效**：激活缓存按（档案 seq / 印象 revision）失效，或把 revision 纳入缓存键；否则新证据永远提醒不到。
- **A4 富化激活输入**：加 FocusFrame 目标 + openLoops（工作记忆里现成的当前任务状态）、预计算的任务标签/摘要（而非仅尾部预览）、近期 cue 效能统计。
- **A5 反馈环**：从档案 process 记录观测"cue → grep 命中 → read 验证 → 证据被引用"，记入 cue 效能 ledger，以统计信号回灌激活（不违反诊断禁令——禁令管印象内容，不管行为统计）。

### B. 存储线：SQLite 三轨检索底座

现状问题：Task Archive 是 `index.json` + Blob 文件，仅能内存扫描做固定串 grep，无索引、无模糊、无语义。

方向：
- **B1 迁库**：Task Archive 原文进 SQLite（`content` 列 + `content_hash` 保完整性），保留证据等级/时间戳/溯源元数据。Experience 流**留 JSONL**（append-only 事件日志语义）。超大 payload 仍走 Blob/Artifacts。
- **B2 证据轨**：`LIKE`/`GLOB`（大小写可选）+ `evidence_rank, created` 排序——与现行 `memory_grep` 语义**字节等价**，是唯一证据路径。
- **B3 词法建议轨**：FTS5 **trigram** tokenizer（中文可检索、子串匹配；≥3 字符，短词 fallback 到 LIKE）。**不用 unicode61**（对中文静默失效）。
- **B4 语义建议轨（可选）**：`sqlite-vec` vec0 向量表，异步/离线 embedding，`embedder_version` 幂等重建；只服务候选建议。
- **B5 混合参数**（抄 QMD）：RRF k=60、query expansion ×2 权重、position-aware 混合；**LLM rerank 不进证据轨**（可作可选建议通道）。
- **B6 后端抽象**：搜索走 `SearchEngine` 接口；vec0 依赖（pre-v1 breaking）坏了可降级 FTS5-only/LIKE，证据轨零依赖扩展。

### C. 评测线：先能量化，再谈优化

现状问题：无记忆能力评测（有单元/golden/对抗测试，但无 recall/成本/能力维度）。

方向：
- **C1 分层评测 L0-L8**：写入提取→检索→事实回忆→时间线→偏好→更新/冲突→遗忘→技能迁移→端到端；**写读分离 + oracle 对照**（grep 确定，检索 vs 阅读瓶颈可精确归因）。
- **C2 cue 质量独立评测**：测试意图 → cue 的锚点/候选串 → grep 命中 → read 到达条目，与 oracle（人工标定相关条目）算重合率。
- **C3 成本必报**：tokens/query + p50/p95。
- **C4 借鉴 QMD bench 范式**：fixture（查询 + 期望文件）+ precision@k / recall / MRR / F1。

### D. 其余已知缺口（记录在案，暂缓）

- **D1 当前真相视图**：档案不可变 ⇒ 被纠正/过期知识永存原文；后续可加"可修订索引层"，新事实 supersede 旧条目时对旧条目**标记失效**（非删除），原始证据链不断（Mem0 invalid / Zep 双时态模式）。
- **D2 程序性记忆**：印象明令禁谈工具/系统行为；后续可设独立、受控的 lessons-learned 机制（避开诊断禁令）。
- **D3 时间过滤查询**：档案有时间戳但检索不支持时间范围（LongMemEval 教训）。
- **D4 MCP 暴露**（可选）：记忆做成 MCP server（add/search/get/update/delete + Resource），即插即用。

## 4. 优先级与依赖

| 优先 | 事项 | 依赖 |
|---|---|---|
| **P0** | B1-B3（SQLite 迁库 + 确定性证据轨 + trigram FTS5）+ A3（缓存失效） | —（地基） |
| **P0** | A1-A2（cue 选择优先 + 解耦） | 依赖 B1-B3 提供候选检索 |
| **P1** | A4-A5（激活输入富化 + 反馈环） | 依赖 A1-A2 |
| **P1** | C1-C2（分层评测 + cue 质量评测） | 可与 P0 并行 |
| **P2** | B4-B5（vec0 + 混合参数）、C3-C4、D1-D4 | 依赖 P0 |

**建议起点**：先做 B1-B3 的 schema 与迁移（证据轨零风险，trigram 解决中文），同时用 C1 的 oracle 框架给现状建基线；A 线等 B 线有候选检索再动。

## 5. 待决问题（open questions）

1. **embedding 形态**：本地 GGUF（重、CJK 用 Qwen3-Embedding）vs OpenAI embedding API（云端、非确定）vs 暂不上向量（FTS5 起步）？→ 倾向：B4 延迟到 P2，先 FTS5-only 验证召回收益，接口抽象保证可后加。
2. **是否引入 LLM rerank**：当前倾向不引入（确定性优先），position-aware blend 可只用 RRF 分实现。
3. **sqlite-vec 依赖**：pre-v1 有 breaking；是否值得引入，还是向量用朴素暴力扫描（本项目规模足够）？
4. **cue 效能 ledger 的形态**：独立表 vs 从档案 process 记录推导。
5. **评测位置**：YUKI.N `test/` 新增 `memory-eval` harness，还是独立脚本目录。
