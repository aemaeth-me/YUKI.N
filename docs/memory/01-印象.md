# 印象（Impression）设计

> 源码：`../../src/Yuki/N/Memory/Impression.hs`，编排：`../../src/Yuki/N/Cognition.hs`，化身配置：`../../src/Yuki/N/Incarnation.hs`

## 1. 概念定位

印象是**一个化身持久性的「潜意识」层**：倾向（tendencies）与显著性（salience），
不是事实、不是承诺、不是任务状态。

- 印象由**独立的模型**维护，与主对话模型分开（每化身可配置 `impressionModel`）。
- 印象**从不自动进入上下文**。它只在一个时机出现：新一轮 run 开始时，激活模型根据
  当前印象状态 + 用户意图 + 任务档案目录，产出 ≤5 条**线索（cue）**，注入到系统消息里，
  供主模型自行决定是否去检索验证。
- 印象**只能被经验证据修订**：每次 run 结束后，固化模型拿到该次 run 的经验事件闭包，
  决定保留/改写/删除哪些印象条目。

一句话：**激活负责「提醒」，固化负责「沉淀」，两者都只是索引，不是证据。**

## 2. 数据结构

### 2.1 印象条目 `ImpressionItem`

| 字段 | 类型 | 含义 |
|------|------|------|
| `id` | Text | 稳定标识；新条目按 `label+intuition` 的 SHA-256 生成（`impression-…`，取 20 hex） |
| `label` | Text | 短标签，≤120 字符 |
| `intuition` | Text | 直觉/倾向的描述，≤1000 字符 |
| `strength` | Double | 强度，必须在 [0,1] |
| `sourceMemoryIds` | [Text] | 遗留字段：Task/档案 ID 引用（只许保留旧值，禁止新造） |
| `sourceExperienceRefs` | [Text] | 证据：经验事件 ID 引用（新条目必须有，且必须在允许集内） |
| `updated` | Integer | POSIX 时间戳 |

### 2.2 印象状态 `ImpressionState`

| 字段 | 含义 |
|------|------|
| `incarnationId` | 所属化身 |
| `revision` | 单调递增修订号（乐观锁基础） |
| `items` | 印象条目列表，**≤24 条** |
| `generatorRevision` | 生成器版本（`impression-consolidation/v3`） |
| `effectiveHash` | `SHA-256(incarnationId+revision+items)`，修订 ID 与审计的指纹 |
| `updated` | 时间戳 |

空状态：`revision=0, items=[]`，hash 按空集计算。

### 2.3 线索 `ImpressionCue`（激活的输出）

| 字段 | 含义 |
|------|------|
| `hint` | 提示文本，≤500 字符（strip 后） |
| `suggestedQuery` | 建议的 `memory_grep` 固定串查询，≤240 字符，可为 null |
| `memoryIds` | 遗留字段：只允许填目录中出现过的 Task/档案 ID |
| `confidence` | [0,1] |
| `reason` | ≤500 字符 |

### 2.4 激活记录 `ImpressionActivation`

每次激活的完整审计：id（`activation-` + SHA-256(化身/任务/run/意图/时间/注入文本/错误)）、
任务/run/意图、所依据的 `stateRevision`、产出的 cues、实际注入文本 `injectedText`、
生成器版本、模型调用 ID、模型名（`provider/model`）、错误（失败时）、创建时间。

### 2.5 修订记录 `ImpressionRevision`

每次固化的完整审计：id（`impression-revision-` + SHA-256(effectiveHash)）、
`beforeRevision`→`afterRevision`、经验引用 `experienceRef`、理由、模型调用 ID、模型名。
`memoryProposals`/`voidProposals` 字段被保留但**禁止使用**（校验强制为空）。

### 2.6 存储 `ImpressionStore`

```haskell
impressionRead          :: Text -> IO ImpressionState              -- 读某化身状态
impressionCommit        :: Text -> Int -> ImpressionState -> ImpressionRevision
                        -> IO (Either Text ImpressionState)        -- CAS 提交
impressionActivationAppend :: ImpressionActivation -> IO ()
impressionActivations   :: Text -> IO [ImpressionActivation]
impressionRevisions     :: Text -> IO [ImpressionRevision]
```

- 持久化到 `impressions.json`，原子写（`atomicEncodeFile`）。
- 内存态由单个 `MVar` 保护；`commit` 用 `modifyMVar` 做**比较-交换**：
  期望 revision ≠ 当前 revision 时返回 `Left "stale impression revision: …"`，绝不覆盖。
- 激活/修订记录各保留最近 **256** 条（`takeEnd 256`）。
- 磁盘加载失败/缺失时优雅回退：缺失→空状态；损坏→报错拒绝启动。

## 3. 激活（Activation）—— 子意识提醒

### 3.1 触发时机

在 `cognitionHooks` 的 `transformContext` 里，**每个根 run 开始**、上下文变换前调用一次
（`../../src/Yuki/N/Cognition.hs` 的 `activationText`）：

1. 从消息里提取最新用户意图（`currentIntent`：ChatUser 最后一条非空文本；
   intentId 取 AGUI 用户 ID，或按 `thread+run+intent` 哈希生成）。
2. 查激活缓存 `cognitionActivationCache`（key = 化身×任务×意图），命中直接复用
   （同一次意图不重复调模型；缓存最多 255 项，按时间淘汰）。
3. 未命中：取任务档案目录（最多 64 个 Task 的 ID），调 `activateImpression`。
4. 成功后把 `renderImpressionCues` 的文本以 `ChatSystem` 消息**插到消息流最前面**
   （`injectSystem`：插在既有 system 消息之后、用户消息之前）。

### 3.2 调用规格（`InvocationSpec`）

| 参数 | 值 |
|------|-----|
| kind | `impression.activate` |
| promptRevision | `impression-activation/v2` |
| 模型 | 化身配置的印象模型（可空 → 用全局模型链） |
| attempts | 每模型 2 次 |
| 输出预算 | 12000 字符 |
| 超时 | 45000ms |
| journal | 记入 `journal.jsonl`（scope: run → memory → invocation → attempt） |

### 3.3 系统提示词（核心约束）

```
You are the private impression activation model for one agent incarnation.
You emit subconscious cues, never recalled facts. You have no tools and may not issue instructions.
Return one JSON object only: {"cues":[{"hint":string,"suggestedQuery":string|null,
"memoryIds":[string],"confidence":number,"reason":string}]}.
Return at most 5 cues. A cue may only suggest a literal fixed-string memory_grep over the
same incarnation's Task Archive; verification requires a subsequent bounded memory_read.
The legacy field memoryIds may contain only Task or archive identifiers present in the supplied
catalog. Never claim that a catalog preview was read evidence. Do not quote archive content.
Empty cues are correct when nothing feels relevant.
```

要点：
- **「线索」不是「回忆的事实」**——措辞上禁止把目录预览当作证据。
- 只建议 `memory_grep` 固定串 + 后续 `memory_read` 验证的检索路径。
- **允许空数组**——没感觉就不提醒，这是显式鼓励的正确答案。
- 用户侧输入三块：`CURRENT IMPRESSION STATE`（JSON）、`CURRENT INTENT`、`TASK ARCHIVE CATALOG`。

### 3.4 输出校验 `parseActivation` / `validateCue`

1. 剥 ` ```json ` 围栏 → `eitherDecodeStrict'` 解析。
2. 只取前 **5** 条 cues。
3. 逐条校验：
   - hint 非空（否则整次激活失败，记 error 审计）；
   - confidence ∈ [0,1]；
   - 每个 `memoryIds` 必须 ∈ 目录 ID 集合（防止幻觉引用）。
4. 通过后裁剪：hint ≤500、suggestedQuery ≤240、reason ≤500（strip 后）。

### 3.5 注入文本

```text
[impression cues — non-factual]
These are subconscious hints, not recalled facts. If relevant, locate evidence with a literal
fixed-string memory_grep, then verify it with a bounded memory_read before relying on it.
- <hint> · suggested grep: <query> · confidence <x>
```

空 cues → 注入空文本、不注入消息。

### 3.6 失败路径

任何失败（解析失败、校验失败、模型失败）都会生成一条带 `error` 字段的激活审计记录
（`injectedText=""`，model 记 `—` 或实际模型），并**返回 Nothing——主对话不受影响**。
激活失败不会重试、不会阻塞 run。

## 4. 固化（Consolidation）—— 经验沉淀

### 4.1 触发时机（事件驱动、异步、幂等）

每个根 run 结束后（`afterRunOutcome` → `closeExperience`）：

1. 追加 run 经验事件（`UserInputAccepted` / `AssistantOutcomeRecorded` / `RunTerminated`）。
2. 追加 `ImpressionConsolidationRequested` 事件（`enqueueConsolidation`），payload 含
   `experienceRef`（最后一个事件 ID）与 `eventIds`（本次 run 的全部事件 ID）。
3. `forkIO` 启动 `drainConsolidations` 后台循环，**按化身加锁**（`withIncarnationLock`），
   串行处理所有未完成（无对应 Succeeded/Failed 事件）的固化请求。
4. 固化成功→追加 `ImpressionConsolidationSucceeded`；失败→`ImpressionConsolidationFailed`
   （error 入 payload）。两者都通过 `appendExperienceIdempotent` 保证**幂等**：
   同一 `operationId`+kind 的事件已存在则跳过。

这使固化在进程重启后也能**从经验流重建队列**（`resumeConsolidations`：启动时对每个
active 化身 fork 一个 drain 循环）。

### 4.2 调用规格

| 参数 | 值 |
|------|-----|
| kind | `impression.consolidate` |
| promptRevision | `impression-consolidation/v3` |
| attempts | 每模型 2 次 |
| 输出预算 | 24000 字符 |
| 超时 | 60000ms |

### 4.3 输入组装

- `PREVIOUS IMPRESSION STATE`：当前印象状态 JSON。
- `TASK ARCHIVE CATALOG IDS`：仅 Task ID 列表（最多 64）。
- `ALLOWED EXPERIENCE SOURCE REFS`：本次 run 的经验事件 ID（`experienceRef : eventIds`）。
- `COMMITTED TASK ARCHIVE / EXPERIENCE CLOSURE`：**经验闭包**——把本次 run 的每个事件
  连同 Blob payload（截断至 14000 字符/事件、总计 50000 字符）编码为 JSON 数组
  （`experienceClosure`）。这是新/改印象必须引用的唯一证据来源。

### 4.4 系统提示词（核心约束）

```
You maintain the persistent subconscious impression state of one agent incarnation.
Impressions are tendencies and salience, not facts, commitments or task state.
Return one JSON object only: {"impressions":[{"id":string,"label":string,
"intuition":string,"strength":number,"sourceMemoryIds":[string],
"sourceExperienceRefs":[string]}],"memoryProposals":[],"voidProposals":[],
"reason":string}.
Return the complete next impression set, at most 24 items. Preserve useful prior impressions
without changing their source refs; remove noise; do not write prompts or execute tools.
Every new or changed impression must cite one or more identifiers from ALLOWED EXPERIENCE
SOURCE REFS in sourceExperienceRefs. Never invent a source ref. Impressions may express
preferences, salience and interpretive tendencies, but must never encode claims or lessons
about tools, APIs, memory_grep, memory_read, search result counts, excerpts, truncation,
context machinery or other internal system behavior. Such diagnostics belong in run records.
sourceMemoryIds is a legacy JSON field: preserve grounded Task/archive refs already present,
or leave it empty; never invent an id. New memoryProposals and voidProposals are forbidden
and both arrays must be empty.
```

要点：
- **完整输出下一套印象集**（不是 diff），≤24 条。
- 旧条目保留时不得改动其 source refs（保持证据可追溯）。
- 新/改条目必须有本次经验证据；**禁止**工具/系统诊断类内容（防「幻觉 grep 命中」污染）。
- `memoryProposals`/`voidProposals` 必须为空（遗留字段）。

### 4.5 校验 `parseConsolidation`（拒绝式验证）

失败即整次固化失败（记 Failed 事件）：

1. ≤24 条；label 与 intuition 非空；strength ∈ [0,1]。
2. `sourceMemoryIds` 必须 ⊆（目录 ID ∪ 旧条目已引用的档案 ID）——**只许沿用，不许新造**。
3. `sourceExperienceRefs` 必须 ⊆（允许经验 ID ∪ 旧条目已引用经验 ID）。
4. **证据要求**：新条目（与旧条目不完全相同的）必须引用本次允许的经验 ID；
   完全不变的旧条目豁免（防止固化被要求重写已沉淀的条目）。
5. **诊断禁令**：label+intuition 折叠小写后不得包含禁用词，含中英文：
   `memory_grep`、`memory_read`、`scannedentries`、`scanned entries`、`grep result`、
   `search result count`、`excerpt window`、`tool call`、`api behavior`、
   `context window`、`截断的检索`、`工具调用`、`接口行为`。
6. `memoryProposals`/`voidProposals` 必须为空。
7. 通过后：为新条目生成稳定 id（`impression-` + SHA-256(label␀intuition) 前 20 hex）、
   裁剪（label ≤120 / intuition ≤1000 / reason ≤1000）、盖 `updated` 时间戳。

### 4.6 提交

- 新 revision = 旧 + 1；`effectiveHash` 重算；经 `impressionCommit` CAS 写入
  （期望 revision 过期则固化失败——两个并发固化不会互相覆盖）。
- 修订记录入审计，`memoryProposals`/`voidProposals` 恒为空数组。

## 5. 迁移与纠错

### 5.1 `migrateKnownFalseImpressions`

加载存储时执行一次**已知错误印象清洗**：删除满足以下任一条件的条目，并把清洗本身记录为
一条 `migration/impression-evidence-v3` 修订：

- 特定伪造 id：`impression-q1r2s3`；
- label 折叠小写等于 `greptruncationawareness`；
- intuition 同时包含 `memory_grep` + `scannedentries`（+ 一个特定污染串）。

理由字段写明：「journal 证据显示该 grep 命中从未存在于归档源中」。这是对历史上
「模型把检索过程幻觉成事实并沉淀为印象」这一已知错误的定点修复，并留下审计。

### 5.2 修订/迁移的统一形态

迁移与正常固化走同一数据结构（`ImpressionRevision` + `before/after` + reason +
invocation/model 元数据），因此**印象状态的全部变化都可审计、可回放**。

## 6. 关键数字

| 量 | 值 |
|------|-----|
| 印象集大小 | ≤24 |
| 每次激活 cues | ≤5 |
| hint / suggestedQuery / reason | ≤500 / ≤240 / ≤500 字符 |
| label / intuition / reason（固化） | ≤120 / ≤1000 / ≤1000 字符 |
| 激活输出预算 / 超时 | 12000 字符 / 45s |
| 固化输出预算 / 超时 | 24000 字符 / 60s |
| 激活/修订审计保留 | 各 256 条 |
| 激活缓存 | 255 项（按时间淘汰） |
| 经验闭包 | 每事件 ≤14000 字符，总计 ≤50000 |
| 档案目录（给激活/固化） | ≤64 个 Task ID |

## 7. 与化身的关系

- 每个化身独立一份印象状态（`impressions.json` 按 `incarnationId` 分键）。
- 化身可配置专用印象模型 `incarnationImpressionModel`（按 name 或 `provider/name` 匹配
  全局模型链）；未配置则用全局模型链。
- 化身归档后不再参与固化队列（`resumeConsolidations` 只处理 active 化身）。
- 印象状态可通过 `self_inspect` 工具被化身自己检查（`activePrompt`、`workingMemory`、
  `impression` 三件套），这支撑「化身能认识并管理自己」的宪法要求。
