# 长期记忆：任务档案、记忆库、经验流与线程简报

> 源码：`../../src/Yuki/N/Memory/Archive.hs`、`../../src/Yuki/N/Memory/LongTerm.hs`、
> `../../src/Yuki/N/Experience.hs`、`../../src/Yuki/N/Memory.hs`、`../../src/Yuki/N/Facts.hs`

## 1. 任务档案（Task Archive）—— 不可变的长期记忆本体

> 源码：`../../src/Yuki/N/Memory/Archive.hs`。这是化身唯一的「事实来源」：
> 原始用户消息、助手回复、推理、工具调用与结果、唤醒包，全部按 run 追加，**只增不改**。

### 1.1 条目 `ArchiveEntry`

元数据（存 `task-archive/index.json`）+ 内容（存 Blob，`contentRef` 指向）：

| 字段 | 含义 |
|------|------|
| `entryId` | `task-entry-` + SHA-256(化身/任务/run/sourceId/kind/内容哈希) 前 40 hex |
| `incarnationId` / `taskId` / `runId` | 域 |
| `seq` / `runSeq` | 任务内全局序号（连续从 1 起）/ run 内序号 |
| `sourceId` | 来源（`task/<run>/<i>/<kind>` 或工具 callId） |
| `kind` | `instruction` / `user` / `reasoning` / `assistant` / `tool-call` / `tool-result` / `wake-packet` |
| `contentRef` / `contentHash` / `contentChars` / `preview` | Blob 引用、SHA-256、字符数、360 字符预览 |
| `parentId` / `callId` / `toolName` | 对话树结构 |
| `created` | 时间戳 |

run 元数据 `ArchiveRun`：runId、化身、任务、源 runId、intentId、状态
（`running`/`completed`/`failed`/`cancelled`/`legacy`）、失败信息、entryIds、created。

### 1.2 追加语义 `taskArchiveAppend`（幂等合并）

- 同一 run 重复追加：**合并**而不是报错——已存在的 sourceId+kind 条目跳过；
  新条目续在后头（run 状态可升级为 sealed）。内容冲突时校验：已存在条目与本次
  内容哈希不同 → 报错「source changed content」；唯一豁免：tool-result 类条目
  允许被更长的版本覆盖（历史截断补偿）。
- 任务内 seq 从当前 head 续号，保证连续（`validateSequences` 加载时强制 1..n）。
- `taskArchiveImportLegacy`：旧 transcript 一次性导入，带 `legacy/<化身>/<任务>` 幂等标记。

### 1.3 检索 `memory_grep`（`taskArchiveGrep`）

代理唯一的长时检索入口。设计要点：

- **确定性固定串扫描**：查询必须单行；逐行逐条目扫描（`occurrenceColumns` 支持多次命中）。
- 候选排序：证据级别（`evidenceRank`：user/tool-result=0 源证据优先，assistant/reasoning/
  instruction/wake-packet=1 派生次之，tool-call=2 垫底）× 时间倒序。
- **进程记录排除**：`memory_grep`/`memory_read`/`self_inspect` 工具自身的调用与结果
  （`processEntry` 识别：toolName 匹配或内容特征匹配）默认排除，`includeProcess` 显式打开。
- 默认种类：user/assistant/tool-call/tool-result；默认当前任务排除（`excludeTaskId`），
  因为其 transcript 已在上下文里。
- 命中带丰富元数据：`evidenceClass`（source/derived/process）、`sourceCompleteness`
  （complete-record / truncated-record / artifact-backed / unknown-source）、
  `artifactIds`、行号、偏移、命中索引/总数、700 字符摘录。
- 结果统计透明：`scannedEntries`、`matchedEntries`、`totalHits`、`returnedHits`、
  `truncated`、`nextOffset`——模型能看到「扫描了多少、截断了多少」，防幻觉。
- 分页：limit ≤100，offset 游标。

### 1.4 精读 `memory_read`（`taskArchiveRead`）

- 以某 entryId 为锚，读它前后 `before`/`after`（各 ≤20）条**同任务**条目。
- `closeEntryGroups`：把与选中条目共享 turn 组/调用组（parentId/callId）的条目
  也纳入窗口（对话树闭合）。
- 字符预算分配：锚点条目 ≥ 一半预算，邻居按 400 字符/条兜底。
- 每条切片带 `contentOffset/contentTotal/truncatedBefore/truncatedAfter`——截断显式化。
- 切片起点偏向锚点命中处（`anchor - wanted/3`），保证看到命中上下文。

### 1.5 目录

- `taskArchiveTasks`：任务摘要（run 数、条目数、首尾时间、最新预览），≤1000。
- `taskArchiveRecent`：最近条目目录，≤256。
- `taskArchiveRuns`：run 列表。

### 1.6 证据分类

`evidenceClass` 把命中分三档：`source`（user/tool-result 原始证据）、`derived`
（assistant/reasoning/instruction/wake-packet 派生文本）、`process`（记忆工具自身的
操作记录）。配合 `sourceCompleteness`，模型可以判断「这条证据是原始的、完整的，
还是派生的、截断的」——**印象与记忆的可信度分层由此而来**。

## 2. 记忆库（LongTerm）—— 可修订的索引层

> 源码：`../../src/Yuki/N/Memory/LongTerm.hs`。注意：**代理没有访问它的工具**；
> 它只通过 HTTP API（`/incarnations/<id>/memories…`）供外部维护，是「人工可修订的
> 长期索引」，与任务档案（机器证据）互补。

### 2.1 数据模型

- `MemorySpace`：owner × visibility（private/shared）构成一个空间，revision 单调。
- `LongMemory`：id（`memory-sha256-` + SHA-256(owner+visibility+规范化内容)）、owner、
  visibility、kind、content、keywords、sourceRefs、revision、created/revised、status。
- **版本历史**：同一 id 的每个修订都保留（Map id → Map revision → memory）；
  加载时强制历史连续（1..n）、身份不变（id/owner/visibility/content/created 恒定）、
  **void 必须终结**（void 后不可复活）。
- `MemoryStatus`：`active` / `dormant` / `void`。
- `MemoryReadReceipt`：每次 grep/read 的回执（action、query、spaces、records、
  created），用于审计「谁读了什么」。

### 2.2 操作

- `remember`：内容规范化（去空白、大小写折叠）后查重——同空间同规范化内容视为
  同一记忆，走**修订**（kind/keywords/sourceRefs 合并，revision+1）而非新建。
- `grep`：混合检索——ASCII 词做分词集合交集、Unicode 词做子串匹配；评分
  `16×整句命中 + 8×Unicode命中 + 4×ASCII命中 + 3×关键词命中`，按
  (score, revised, revision) 排序；每条返回 240 字符上下文摘录（`snippetAround`）。
- `read`：按 id + 可选 revision 读取，默认最新；可见性校验（shared 或 owner 自己）。
- `void`：仅 owner 可 void，期望 revision 必须匹配，void 产生新修订（status=void）。
- `receipts`：读取回执按时间倒序。

所有写操作 CAS 于 MVar 内完成；磁盘格式带 `version` 字段，版本不匹配拒绝加载。

## 3. 经验流（Experience）—— 唯一的时序事实源

> 源码：`../../src/Yuki/N/Experience.hs`

- 每化身一条流（`experience/<化身>`），追加写 `events/events.jsonl`。
- 事件 `ExperienceEvent`：eventId（SHA-256(stream+seq+kind+payloadHash)）、
  operationId、actorId、intentId、taskId、runId、delegationId、causationId、
  streamId、**seq（连续、从 1 起）**、kind、payloadRef、payloadHash、occurredAt。
- 追加带期望光标（`Maybe ExperienceCursor`）校验，防并发重放。
- 加载时强制 seq 连续；损坏行报错定位行号。
- 事件类型（认知层产生）：`UserInputAccepted`、`AssistantOutcomeRecorded`、
  `RunTerminated`、`ImpressionConsolidationRequested`、`ImpressionConsolidationSucceeded`、
  `ImpressionConsolidationFailed`、迁移类（`LegacyTranscriptImported` 等）。
- 它同时服务：工作记忆光标（head）、固化队列重建（drain 幂等）、经验闭包（固化证据）、
  审计（HTTP `/experiences`）。

## 4. 线程简报（ThreadBrief）与事实缓存 —— 旧版轻量记忆

> 源码：`../../src/Yuki/N/Memory.hs`（watcher）、`../../src/Yuki/N/Facts.hs`（事实缓存）

这是重设计前的记忆机制，仍存在于代码中（主要服务于确定性回放与 HTTP `/memory/*` 接口）：

- **Watcher**（`memoryHooks`）：每轮 run 结束时，把新消息喂给一个小模型
  （`watcherPrompt`：previous summary + delta），返回 JSON：
  `{summary, memorize[], retrieve|null, invalidate[]}`。
  - summary 滚动合并（≤2000 字符），存为 `ThreadBrief`（`threads/<id>.json`，
    附最近 3 个 episode，保留 64 个）；
  - memorize → FactStore（内容去重、最多 4096 条、检索 top-3 词重叠打分、
    无使用记录且过期的可归档、invalidate 置 void）；
  - retrieve → 检索候选注入（`[memory candidates]`，≤1200 字符），
    每 run 检索预算 3 次 + 查询冷却 5 轮。
  - 全部包在 `insulate`/`shield` 里：watcher 失败绝不影响主对话。
- **注入标记**：`[thread brief]` 与 `[memory candidates]` 是显式标记，Replay 靠它们
  识别「记忆注入的消息」并做确定性还原（`replayWithStores` 用 journal 里记录的
  `StoreBriefEntry`/`StoreFactsEntry` 重放 watcher 行为，保证模型输入逐字节一致）。

新架构下代理的长期记忆走任务档案（grep/read），ThreadBrief 体系退居兼容与回放层。
