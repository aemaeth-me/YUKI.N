# 05 记忆与睡眠

## 这位 Yuki 记得什么

每位 Yuki 拥有独立的长期记忆体系，跨它的主对话与全部任务共享：

- **Task Archive（长期记忆）**：不可变、只追加的原始经历——用户输入、
  模型回答、推理与工具记录，覆盖全部任务（含已归档）。Worker 的经历也
  经 delegationId 关联进同一份档案。
- **提炼记忆**：从档案归纳出的索引（事实、偏好、工作方法），带出来源，
  可修订。
- **印象**：潜意识的非事实性提示（显著性与解释倾向），由独立的内部
  模型在 Run 结束后归纳，只作为检索线索出现。
- **工作记忆**：当前上下文（短期），按对话/任务分别维护。

另一位 Yuki 永远检索不到这份档案；删除 Yuki 时一并删除。

## Agent 如何使用记忆

- 需要事实时：先 `memory_grep`（固定字符串扫描档案定位条目），再
  `memory_read`（围绕条目有界读取），引用时会带上 taskId/entryId/runId。
- 印象只作为 grep 线索；Yuki 被明确要求不把印象当事实。
- Worker 可以用同样的只读工具检索，但不能写入。

## 睡眠（Sleep）与上下文压缩

上下文接近模型窗口时，Yuki 会进入**睡眠**：冻结当前上下文纪元，裁决
遗忘项，压缩为摘要并携带 Wake Packet 在同一会话中醒来继续。原文不丢
——仍在本机的 Blob / Experience / Journal 中可审计，只是不再占用活跃
上下文。

触发是自动的（每次模型调用前按窗口余量计算，见
[06-配置](06-配置.md) 的上下文策略），Agent 也可以主动调用 `sleep`。

界面上你会看到状态卡的阶段变为「压缩上下文」或「睡眠」，上下文条
显示当前估算占用。

## 当前版本的可见性

新工作台暂未提供记忆/印象/睡眠的检视页面（可用
[07-HTTP与事件](07-HTTP与事件.md) 中的 memory 端点查询）；睡眠行为本身
不受影响，照常发生。
