# 10 已知限制

当前版本的功能缺口与有意取舍。按影响排序，后续版本优先处理前四项。

## 缺口（会用 workaround 补上之前需要 API）

1. **不能在界面创建/归档/删除 Yuki**：集群总览只读。
   绕行：`POST /incarnations`、`POST /incarnations/:id/(archive|delete)`。
2. **不能在界面编辑能力配置**：主对话（Yuki 默认能力）与任务的
   provider/model/gate/上下文策略不可视编辑；派发草案的能力快照只读。
   绕行：`PUT /config/threads/:id`。
3. **任务归档/恢复/fork/导入导出无界面**：任务列表仅展示。
   绕行：`POST /threads/:id/(archive|restore|fork)`、`/threads/import|export`。
4. **记忆/印象/睡眠无检视页面**：记忆只能被 Yuki 自用或通过 API 查询
   （见 [07-HTTP与事件](07-HTTP与事件.md) 的记忆端点）。

## 取舍（设计使然，但可能让你意外）

5. **非 git 目录中 shell 造成的文件改动不进变更台账**。变更视图不是
   「全部文件变化」，而是「工具写入（权威）+ git 补记」。
6. **失败/被取消 Run 的最终文本不进交付流**（只记成功根 Run）；其
   完整过程仍在 journal 可查。
7. **监控流断线时只有降级徽标**：活动面板在断流期间停更（暂无轮询
   回退），恢复后自动继续。
8. **主对话不可清空**：它是持久主会话；重新开始一位 Yuki 的彻底方式
   是删除并重建该 Yuki。
9. **Worker 产生的交付记录 runKind 随其父 Run**：在交付视图按来源
   区分 Worker 时会有归属误差（可按 runId 关联真实层级）。
10. **Worker 不可见异步 Worker 的过程事件**：它的状态卡是遥测投影；
    过程细节在 Run 监控与 journal 中查看，不混入父对话流。
11. **并行上限是软保护**：`sub_agent_spawn` 的注册窗口理论上可超额 1
    个活跃 Worker。
