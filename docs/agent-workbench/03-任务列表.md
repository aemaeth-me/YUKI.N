## P0｜地基（后端）

### P0-B1 SessionKind 落地（Specs §1.1）

- 目标：`SessionMeta` 增加 `sessionKind`，JSON 缺省 `task`，零迁移。
- 改动：`src/Yuki/N/Sessions.hs`（类型、JSON、store 约束）、`Server.hs`
  （archive/restore/fork/delete 对 Home 返回 400）。
- 验收：存量 `sessions/index.json` 直接加载；Home 归档请求 400
  `home_session_immutable`；既有 session 测试全绿 + kind 往返测试。

### P0-B2 Run 树索引（Specs §1.3）

- 目标：RunRegistry 扩展 RunDescriptor（incarnation / parent / kind /
  objective / startedAt），新增 `activeRuns / childrenOf`。
- 改动：`src/Yuki/N/Runs.hs`；`Agent.hs` 注册调用处（根 Run 由 Server
  解析 thread→incarnation/kind 传入）；`SubAgent.hs`（Worker：parent=父
  runId、kind=RunWorker、objective=prompt 截断）。
- 验收：注册/注销/树查询单元测试；同步 sub_agent 运行时可见父子两条
  记录；并发注册/注销无泄漏（registry 终态为空）。

### P0-B3 Telemetry：LiveStatus 投影 + ActivityHub（Specs §1.4、§5.2）

- 目标：新模块 `Yuki.N.Telemetry`：LiveStatus 类型与 store、事件 projector
  （经 `observeEvent` hooks 链接入每个 Run）、ActivityHub（TChan 广播 +
  发布 + 200ms 节流合并 status）。
- 改动：新建 `src/Yuki/N/Telemetry.hs`；`Agent.hs` / `Yuki.N.hs`（hooks
  组合与装配）；phase 推导规则按 Specs §1.4。
- 验收：run 全生命周期中 LiveStatus 字段随事件正确演化（STEP/TOOL/
  context.status/usage/sleep/cancel 各路径有测试）；projector 抛错不影响
  run（fail-open 测试）；hub 无订阅者不积压；同 run 200ms 内多事件只发
  最后一帧 status。

### P0-B4 Telemetry：交付台账 + FS 变更台账（Specs §1.5、§1.6、§4.5）

- 目标：deliveries.jsonl 与 fs-changes.jsonl 追加 store；fs 写工具包装；
  run 终局钩子（Answer 交付 + git 增强）。
- 改动：新建 `src/Yuki/N/Telemetry/Ledger.hs`；`Tools.hs`（`workTools`
  出口包装写/编辑/删除类，diff 用 `Domain.Diff.unified`，fail-open）；
  `Agent.hs` 终局（Answer 记录；cwd 在 git 仓库时只读 `git status
  --porcelain` / `git diff --stat HEAD`，3s 超时静默失败，求差补 OriginGit）；
  `Config.hs`（`YUKI_TELEMETRY_*`）。
- 验收：写工具成功 → 台账记录含路径/op/diff；写工具失败 → 无记录；
  artifact 溢出 → DeliveryArtifact；根 Run 正常结束 → DeliveryAnswer
  （Worker 不记）；git 仓库中 shell 新建文件 → run 结束后出现 OriginGit
  记录；非仓库 shell 变更 → 无记录且不报错；台账写入异常不影响 run。

## P1｜集群与工作台闭环

> 目标：集群总览默认落点；Yuki 工作台（现在/主对话/任务/交付/变更）；
> 手动派发闭环；监控 SSE 流驱动全部实时状态。

### P1-B1 Home 会话端点（Specs §2.1、§2.2）

- 目标：`GET /incarnations/:id/home` 幂等 ensure；`GET /threads?kind=`。
- 改动：`Sessions.hs`（`ensureHomeSession`，id=`home-<incarnationId>`）；
  `Server.hs`；删除 Yuki 连带删除 Home。
- 验收：重复 GET 同一 threadId；`kind=task` 列表不含 Home；归档 Yuki
  后 404；删除 Yuki 后 Home 消失。

### P1-B2 DispatchDraft store 与草案生成（Specs §1.2、§2.3 上半）

- 目标：DispatchDraft 持久化 store；`POST /incarnations/:id/dispatches`
  （Invocation 起草 + 回退）；`GET / PATCH`；草案事件发布到 ActivityHub。
- 改动：新建 `src/Yuki/N/Dispatch.hs`；`Server.hs`；`Yuki.N.hs` 装配
  （`<dataDir>/dispatches.json`）。
- 验收：草案含 title/prompt/config 快照；模型不可用时回退且
  generation=fallback；重启后草案在；PATCH 仅 draft 可改（409 测试）；
  新建草案产生 hub `draft` 帧。

### P1-B3 Dispatch confirm/cancel（Specs §2.3 下半）

- 目标：confirm 原子创建任务（meta+config+transcript 首条）；cancel 终态；
  resolved 帧发布。
- 改动：`Yuki.N.Dispatch`（confirm 编排、失败回滚）；`Server.hs`。
- 验收：confirm 后任务出现于 `kind=task` 列表、config 落盘、transcript
  首条=draft.prompt；重复 confirm 409；注入失败不留半成品；cancel 终态；
  confirm/cancel 均产生 `draft.resolved` 帧。

### P1-B4 Activity 端点 + 监控 SSE 流（Specs §1.7、§2.4、§2.5、§5.3）

- 目标：`GET /incarnations/:id/activity`（富化）、`GET /fleet`、
  `GET /activity/stream`（snapshot 首帧 + 六种增量帧 + 15s 心跳）。
- 改动：`Server.hs`；`Telemetry.hs`（快照组装）；dev-server 代理 SSE
  配置。
- 验收：快照无副作用（重复调用一致）；流连接后先收 snapshot；run 状态
  变化产生 status 帧且节流正确；run 终局帧序正确（delivery/fschange 先
  于 run.end）；多连接各自收全；慢消费不阻塞 hub。

### P1-B5 交付与变更查询端点（Specs §2.6）

- 目标：`GET .../deliveries`、`GET .../fs-changes`（过滤 + 游标分页）。
- 改动：`Server.hs`；`Telemetry/Ledger.hs`（读侧）。
- 验收：倒序、hasMore/nextOffset 正确；threadId/runId 过滤正确；limit
  上限生效；空台账返回空集不报错。

### P1-F1 前端新骨架 + 集群总览（04 §一、§二、§3.1、§四、§五）

- 目标：`Browser.application` + URL 路由；TelemetryState 全局归并；
  activity.js（EventSource + 降级轮询 + 顶栏连接态）；集群总览视图。
- 改动：`frontend/` 骨架重写（`Yuki.App.*`、`Yuki.Telemetry.*`、
  `Yuki.Fleet.*`、`Yuki.Protocol.*` 重组 Decode/Encode/Request）；
  `web/activity.js` 新增。
- 验收：启动默认落 /fleet；卡片三态（active/waiting/idle）与实时更新
  正确；事件带追加；监控流断开 → 降级轮询 + 可见标记 → 恢复自动切回；
  刷新/深链还原视图。

### P1-F2 工作台框架 + 现在视图 + RunStatusCard（04 §3.2、§3.6）

- 目标：工作台导航与布局；now 视图（等待用户区 + Run 树 + 最近交付）；
  RunStatusCard 组件（含 steer/取消行内操作）。
- 改动：`Yuki.Workbench.*`、`Yuki.Run.StatusCard`、`Yuki.Run.Tree`。
- 验收：三层树正确嵌套；状态卡全部字段与 journal 对照一致；耗时本地
  插值；steer/取消直达任意 runId 生效；run.end 后卡片灰化 30s 消失。

### P1-F3 主对话面板 + 派发对话框（04 §3.3、§3.7、§3.4）

- 目标：`<ConversationPanel>` 组件化（迁移现有消息/工具卡/SubAgent 卡
  渲染件）；主对话视图（Home，隐藏归档/fork，常驻「派发任务」）；
  派发对话框全流程；任务列表视图。
- 改动：`Yuki.Conversation.*`、`Yuki.Dispatch.*`、`Yuki.CapabilityFields`。
- 验收：Home 聊天闭环（发送/流式/steer/取消/重试）；派发：需求 →
  草案 → 编辑 → confirm → 任务详情自动首 Run（末条未应答 user 才发起）；
  能力快照编辑生效；刷新任务详情不重复发起。

### P1-F4 任务详情 + 交付视图 + 变更视图（04 §3.5、§3.8、§3.9）

- 目标：任务详情四页签（对话/交付/变更/配置）；交付流与展开；变更流
  与 diff 渲染；「未经追踪」提示。
- 改动：`Yuki.Delivery.*`、`Yuki.Changes.*`、能力页迁入页签。
- 验收：三类交付正确展示与定位；diff 渲染正确；git 来源标注正确；
  非仓库 shell 提示出现；分页游标正确。

### P1-F5 Run 监控 + 二级导航迁移（04 §3.10、§3.11）

- 目标：Run 监控视图（状态头 + 事件时间线 + 交付/变更过滤 + steer/
  取消；历史 run 走 journal trace）；Memory/Self/Audit 迁入二级导航。
- 改动：`Yuki.Run.Monitor`；既有 Memory/Self/Audit 视图适配新骨架。
- 验收：活跃 Run（本连接持有）时间线实时；非本连接 Run 显示状态卡 +
  可操作提示；历史 run trace 渲染；记忆/自我/检查功能不回归。

### P1-T1 端到端

- golden/E2E：Home run；派发 confirm → 首 Run；activity/fleet 快照形状；
  监控流帧序；台账记录；Home 归档 400；旧 sessions 文件加载。
- 前端：若仓库无前端测试基准则以手动验收清单替代（对照 01 §十二）。

**P1 出口标准**：01 §十二 验收场景第 1–4、8–10 条全过；测试全绿。

## P2｜主动编排

> 目标：Yuki 可提议派发（用户确认）；Orchestrator 拥有异步 Worker
> 工具组；用户可直达任一 Worker。

### P2-B1 完成表与终局钩子（Specs §1.3 [P2]、§5.1）

- 目标：RunRegistry 完成表；runAgent 三处终局写入；父注销清理子树。
- 改动：`Runs.hs`、`Agent.hs`。
- 验收：Worker 完成后 completion 可查；父注销后子树条目清除；取消
  路径 outcome=cancelled。

### P2-B2 `propose_dispatch` 工具（Specs §4.2）

- 目标：工具注册（Home/任务可见、Worker 剔除）、`dispatch.draft` 流内
  事件、阻塞等待裁决（超时/取消语义）。
- 改动：`Yuki.N.Dispatch`、装配处注册、`SubAgent.hs` 的
  `workerDeniedTools` 同步剔除。
- 验收：确认→工具返回 threadId；取消/超时→isError 返回；run 取消不
  挂死；Worker 工具列表无此工具；`YUKI_DISPATCH_CONFIRM_TIMEOUT` 生效。

### P2-B3 异步 `sub_agent_*` 工具组（Specs §4.3、§5.1、§5.4）

- 目标：spawn/send/status/list/wait/cancel；完成通知注入 + `worker.notice`；
  级联取消（递归）；并行上限。
- 改动：`SubAgent.hs`（异步路径 forkIO + 注册 + 注入）；`Runs.hs`
  （children 索引、级联）；`Agent.hs`（轮次边界 emit `worker.notice`）；
  `Config.hs`（`YUKI_SUBAGENT_MAX_PARALLEL`）。
- 验收：spawn 立即返回父 Run 继续；父收到完成系统消息与 notice 事件；
  wait 收齐/超时正确；取消父 → 全部 Worker 终止（含递归）；并行上限
  错误明确；越权查询他人 Worker 被拒。

### P2-B4 delegationId 填充（Specs §8）

- 目标：`appendRunEvents` 携带 delegationId（同步/异步 callId）。
- 改动：`SubAgent.hs`（传递 callId 入子 Run 上下文）、`Cognition.hs` /
  `Experience.hs`。
- 验收：Worker run 的 Experience 事件 delegationId 非 Nothing；无委派
  仍为 Nothing；replay 行为不变。

### P2-F1 派发卡片 + 等待事项（04 §3.3、§3.2）

- 目标：`dispatch.draft` 流内卡片（编辑/确认/取消）；`draft.resolved`
  终态锁定；集群总览与工作台等待区联动。
- 改动：`Yuki.Dispatch.*`、`Yuki.Telemetry.*`（draft 帧归并）。
- 验收：提议→卡片→确认→任务出现全链路；多标签页状态收敛；拒绝后
  Yuki 继续对话；集群卡片等待计数正确。

### P2-F2 Worker 直达与异步详情（04 §3.6、§3.10、§九）

- 目标：异步 Worker 状态卡（Telemetry 驱动）与 Run 监控详情；steer/
  取消直达。
- 改动：`Yuki.Run.*`。
- 验收：异步 Worker 从 spawn 到 run.end 状态全程可见；steering 到达
  运行中 Worker；取消生效；详情展示结局与结果摘要。

### P2-T1 端到端

- E2E：propose_dispatch 确认/拒绝/超时；异步 Worker 全生命周期
  （spawn→notice→wait→级联）；并行上限；delegationId 断言；监控流
  run.end/draft 帧。
- golden：异步路径新增独立 golden，不改既有 golden。

**P2 出口标准**：01 §十二 验收场景第 5–7 条全过。
