## 可见实体

```text
Yuki（后端：Incarnation）        持续主体
├── 自我                         名称、方向、Prompt 版本与生命周期
├── 记忆                         印象、长期记忆、工作记忆与睡眠
└── 任务（后端：Thread）         一项可命名、暂停、恢复和归档的持久工作
    ├── 对话 / Transcript         任务经历的可读投影
    └── 运行（后端：Run）         一次执行尝试
        ├── 模型轮次与工具调用
        └── 子代理 / Worker       本次运行内的临时执行者
```

- **Yuki** 是用户切换的最高持久主体。`Incarnation` 保留为代码与接口术语，不在
  中文界面中翻译成“分身”或“语境”。
- **任务**对应 `Thread`。它拥有标题、工作目录、任务级配置、Transcript、运行历史
  与归档状态；它不拥有 Yuki 的人格或长期身份。
- **运行**对应 `Run`，是任务的一次执行。重试会产生新运行，不会产生新 Yuki 或
  新任务。
- 当前实现没有独立的持久 `Session` 或 `Conversation` 实体。`Sessions` 模块是
  Thread 元数据服务；`Conversation` 只是 Transcript 的界面形态。
- 子代理不形成持久主体。它是 Run 内的临时 Worker，其活动、输出、错误和上下文
  归入该 Run 的因果与审计链。

## 记忆归属

| 对象 | 归属 | 当前权威来源 |
| --- | --- | --- |
| 印象 | Yuki | Impression store 及 revision / activation |
| 提炼长期记忆 | Yuki | Long-term memory index，带来源与版本 |
| 任务记录 | Yuki → Task | Task Archive，原始结构化经历 |
| 工作记忆 | Yuki → active Task | WorkingMemory / FocusFrame |
| 睡眠周期 | Yuki → Task / Run | SleepCycle / ContextEpoch |
| Transcript | Task | 可恢复的执行投影，不是长期身份本体 |

## 配置归属

- Yuki：名称、方向、印象模型、Charter/Composite Prompt 版本与激活状态。
- Task：cwd、provider、model、reasoning effort、文件/Shell/记忆 gate、上下文策略。
- Run：实际模型调用、token、轮次、耗时、工具和事件快照；Run 历史不可被后续
  Task 配置改写。
- Root：共同 Root Prompt 版本与系统审计；是控制面，不是可接收日常任务的 Yuki。

## 信息架构

- **对话**：当前任务的正文与在途状态；工具、推理、确认和子代理就地展开。
- **任务**：创建、切换、命名、归档、恢复、分叉、导入、导出与继续历史任务。
- **记忆**：印象、长期（任务原件 / 提炼索引）和睡眠三个明确层次。
- **能力**：当前任务的真实模型、provider、cwd、工具 gate 与上下文策略。
- **自我**：Yuki 元数据、Prompt 生成/编辑/版本/激活与生命周期。
- **检查**：从回复、工具、记忆来源和运行就地进入；完整 Run / Journal / Artifact
  索引保留为低频检查工作面。

正式界面不使用“工作语境”作为产品实体。艺术概念稿中的边缘入口、纸面、景深和
渐进显现只作为表达手段，不能改变以上生命周期或隐藏关键操作。

## 功能迁移边界

| 领域 | 正式入口 | 保留的关键能力 |
| --- | --- | --- |
| 对话 | 对话正文 | 流式文本与推理、工具参数/输出、确认、中止、引导、追问、重试、复制 |
| 子代理 | 对话中的运行材料 | 状态、活动、上下文用量、增量输出、失败与孤立结果 |
| 任务 | 下沿快速切换与任务页 | 新建、命名、归档/恢复、分叉、导入/导出、历史继续 |
| 记忆 | 右沿印象与记忆页 | 印象、激活/修订、任务原件检索、长期索引、版本、读取收据、工作记忆与睡眠 |
| 能力 | 能力页 | cwd、路径补全、运行入口、provider/model/effort、能力 gate、上下文策略与全局继承来源 |
| 自我 | 左沿 Yuki 与自我页 | 创建/切换/归档/恢复、名称、方向、印象模型、Prompt 生成/编辑/激活/版本 |
| 检查 | 检查页与正文 drill-in | Run 摘要、耗时、Journal 事件、请求响应、工具、Artifact 与重放核验 |

恢复 Transcript 时，消息与工具调用按标识重建因果关系；缺少父消息的工具结果不会
被丢弃，而是作为“恢复的工具材料”显示。未知扩展事件降级为可忽略事件，字段不完整
但能够归属的子代理事件保留其原始材料，避免单个扩展破坏整段对话。

## 来源与检索约束

- Task Archive 的检索结果区分候选记录数、实际命中记录数、命中总数、当前页数量
  与后续 offset；`scannedEntries` 只表示候选记录，绝不能解释为命中数量。
- 默认搜索用户输入、模型回答与外部工具结果，但排除 `memory_grep`、`memory_read`
  和 `self_inspect` 自身产生的调用/结果；诊断时可显式包含过程记录。
- 同一行的每一处字面命中都返回独立位置。任何分页或省略都必须通过
  `hasMore / nextOffset` 明示，不能依靠截断预览暗示。
- 工具结果标注来源类型、内容完整性、call id 与 artifact id。Shell、文件读取或
  工件读取无法证明上游来源完整时，界面必须显示“无法确认来源完整性”，不能把
  当前保存片段冒充完整原件。
- 印象只容纳偏好、显著性与解释倾向。新建或修改印象必须引用本次真实 experience
  事件；工具行为、检索计数、截断规则和上下文机制等诊断结论只进入 Run / Journal，
  不进入潜意识印象。
- “检查”的默认过程面使用聚合 Run Trace；原始 Journal、API 请求与全部条目仍在
  次级 facet 中完整保留。聚合只折叠展示，不改写或删除原始因果记录。

## 渐进演进

当前持久化没有独立 `Session`，因此界面不凭空建立第三层。如果未来需要跨任务共享
短期状态，应先在后端定义其所有权、恢复边界与归档语义，再决定是否引入“空间”或
“会话”。同理，长期记忆索引可以重建，Task Archive 和 Journal 才是来源原件；未来
调整提炼策略时不得把索引提升为不可追溯的权威历史。
