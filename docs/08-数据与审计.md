# 08 数据与审计

## 数据目录（默认 `~/.yuki-n`）

```text
journal.jsonl                  每次 Run 的效应日志（回放/审计源）
sessions/index.json            主对话与任务的元数据
threads-config/<id>.json       任务级配置
transcripts/<id>.json          对话投影
dispatches.json                派发草案（待确认与历史）
deliveries.jsonl               交付台账（答案/文件/artifact）
fs-changes.jsonl               文件系统变更台账
objects/ + index.jsonl         artifact 正文与索引
providers.json                 多 provider 注册表（可选）
cognition-v2/                  每位 Yuki 的记忆体系
  incarnations.json            Yuki 注册表
  events/events.jsonl          经历事件（含 delegationId）
  task-archive/                长期记忆档案
  long-term.json               提炼记忆
  impressions.json             印象
  working/working.json         工作记忆与睡眠周期
  context-epochs.json          上下文纪元
  payloads/sha256/...          内容寻址 blob
```

删除 `deliveries.jsonl` / `fs-changes.jsonl` 只损失交付/变更视图的历史，
不影响任何运行与记忆功能。删除整个目录 = 全新开始。

## 备份

停机后复制 `YUKI_DATA_DIR` 即可。运行中复制 journal 以外的文件也是
安全的（journal 是追加写，复制可能截到半行——启动时会修复未终止的
尾部）。

## Journal 回放

```console
cabal run yuki-n -- replay ~/.yuki-n/journal.jsonl [RUN_ID]
cabal run yuki-n -- anatomy ~/.yuki-n/journal.jsonl
```

`replay` 对照日志重放并对账（hooks 确定时逐事件一致）；`anatomy` 输出
单 Run 的结构化解剖报告。界面侧用
`GET /journal/runs/:id/(summary|trace)` 查看等价信息。

## 台账语义

- **交付**（deliveries.jsonl）：答案仅记录成功结束的根 Run；文件与
  artifact 记录所有 Run（含 Worker）。Worker 记录的 runKind 暂随其父
  （真实层级可按 runId 关联）。
- **变更**（fs-changes.jsonl）：`fs_write`/`fs_edit` 成功执行的工具记录为
  权威（含 diff）；git 仓库中 shell 等绕开工具的改动在 Run 结束后由
  `git status/diff` 补记（只留 stat）；其余改动不记录。
- 两者都是只追加日志，按 incarnation/thread/run 过滤查询。

## 遥测的易失性

活跃 Run 状态（LiveStatus）、Run 树、完成表只活在进程内。重启后
「现在」为空是正常的——持久的历史在 journal、transcript 与两份台账里。
